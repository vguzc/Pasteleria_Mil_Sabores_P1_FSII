1. Introducción

1.1 Propósito

El presente documento tiene como objetivo formalizar la Especificación de Requisitos de Software (ERS) para la plataforma web de comercio electrónico y administración de Pastelería Mil Sabores, en el marco de la celebración de sus 50 años de trayectoria artesanal (1976 – 2026). La especificación establece los lineamientos funcionales, requerimientos no funcionales, estructura de componentes en React 18, esquema de persistencia local reactiva y la batería de pruebas unitarias automatizadas con Jasmine y Karma exigidas en la asignatura Desarrollo Fullstack II (DSY1104).

1.2 Alcance del Sistema

El sistema comprende una aplicación web de página única (SPA) modular dividida en dos grandes ámbitos operativos:

  • Módulo Público (Tienda Clientes): Catálogo interactivo de 8 categorías oficiales, ficha técnica de productos, selector de inventario con tope físico, carrito reactivo con cálculo de IVA y despacho, checkout asistido con autocompletado y comunas de Chile, comprobante con boleta electrónica imprimible, gestión de reclamos/contacto y secciones conmemorativas de blog y recetas.
  • Módulo Administrativo y Vendedor: Dashboard analítico de ventas y órdenes, mantenedor CRUD de catálogo de productos con detección de stock crítico (≤ 6 unidades), mantenedor CRUD de categorías, control de usuarios y roles, reportes financieros y modal tributario para visualización y reimpresión de boletas.

1.3 Definiciones y Acrónimos

Término / Acrónimo Definición Técnica
SPA Single Page Application. Aplicación web cargada en una sola página con actualización dinámica sin recarga completa.
SRP Single Responsibility Principle. Principio donde cada componente React encapsula una sola funcionalidad.
SKU Stock Keeping Unit. Identificador alfanumérico único para control individual de productos en bodega.
Módulo 11 Algoritmo estándar oficial utilizado por el Servicio de Registro Civil e Identificación de Chile para validar el dígito verificador del RUN.

3. Requerimientos Funcionales (RF)

A continuación se formalizan los 18 requerimientos funcionales del sistema bajo estándar tabular de ingeniería:

3.1 Módulo Tienda Pública (Clientes)

RF-01: Catálogo y Búsqueda Multicriterio de Productos
DescripciónEl sistema debe mostrar los productos en una grilla paginada permitiendo filtrado simultáneo por 8 categorías oficiales (Tortas Cuadradas, Tortas Circulares, Postres Individuales, Sin Azúcar, Tradicional, Sin Gluten, Veganos y Especiales), ordenamiento por precio o nombre y búsqueda por texto.
EntradasTérmino de búsqueda, categoría seleccionada, criterio de ordenamiento.
SalidasColección de tarjetas de productos que satisfacen los filtros aplicados.
Criterio AceptaciónLa actualización del catálogo ocurre en menos de 100 ms de forma reactiva sin recarga de página.
RF-02: Ficha Técnica Detallada de Producto
DescripciónPresenta imagen en alta resolución, nombre, SKU, precio normal y rebajado, descripción organoléptica, porciones recomendadas, stock disponible y selector numérico de unidades acotado al stock físico.
EntradasIdentificador del producto (SKU).
SalidasVista de detalle con controles de compra y feedback de disponibilidad.
Criterio AceptaciónEl selector no permite seleccionar cantidades superiores al stock disponible en bodega.
RF-03: Vista Especializada de Categorías
DescripciónRenderiza una grilla superior de tarjetas con las categorías oficiales y un contenedor inferior dinámico que lista los productos de la categoría seleccionada al hacer clic.
Criterio AceptaciónCoincidencia estructural con la Figura 4 de la pauta de evaluación Duoc UC.
RF-04: Sección de Ofertas Especiales
DescripciónFiltra automáticamente los productos marcados con indicador promocional activo o precio anterior tachado, exhibiendo el porcentaje de ahorro.
Criterio AceptaciónMuestra solo productos donde enOferta === true.
RF-05: Carrito de Compras Dinámico y Validación de Cupones
DescripciónAdministración de ítems en carrito con modificación de cantidades y remoción. Cálculo automático de Subtotal, Descuento, IVA (19% incluido) y Costo de Envío ($3.990 estándar o $0 si la compra supera $30.000). Validación de cupones institucionales: FELICES50 (50% OFF mayores de 50 años), DUOC10 (10% OFF comunidad Duoc UC) y ESPECIAL18 (15% OFF).
Criterio AceptaciónCoincidencia matemática exacta y persistencia del carrito en LocalStorage.
RF-06: Checkout Asistido con Autocompletado
DescripciónFormulario de despacho con selección en cascada de Regiones y Comunas de Chile. Si el usuario cuenta con sesión iniciada, todos los campos de cliente y dirección se completan automáticamente. Integra switch para simular pago aprobado vs rechazo bancario.
Criterio AceptaciónAutocompletado transparente de datos de perfil e integridad referencial del pedido.
RF-07: Comprobante de Compra y Emisión de Boleta Electrónica
DescripciónGenera la confirmación con correlativo único (ej. #20240705), tabla de productos, totales y botón para imprimir Boleta Electrónica en PDF optimizada para impresión física.
Criterio AceptaciónLa vista de impresión omite barras de navegación y adapta la boleta a tamaño carta.
RF-08: Gestión de Pago Bancario Rechazado
DescripciónDespliega notificación descriptiva de error en la transacción financiera, preservando los datos del carrito e incluyendo botón para reintentar el pago.
Criterio AceptaciónCoincidencia visual con la Figura 8 de la pauta Duoc UC.
RF-09: Registro de Usuarios con Algoritmo Módulo 11
DescripciónFormulario de registro con validación matemática estricta de RUN chileno (Módulo 11), formateo automático de nombres en Title Case y cálculo de edad para asignación automática del cupón Senior 50+.
Criterio AceptaciónRechazo de RUNs inválidos antes de persistir la cuenta de usuario.
RF-10: Panel Privado del Cliente (Mi Cuenta)
DescripciónVisualización de datos de perfil, historial de órdenes previas con reimpresión de boleta y catálogo de cupones personales disponibles.
Criterio AceptaciónAcceso restringido únicamente al titular de la sesión activa.
RF-11: Secciones Multimedia (Blog y Recetas)
DescripciónPublicación de artículos conmemorativos de los 50 años y receta de Pasteles de Belém con lista de ingredientes y video tutorial embebido de YouTube.
Criterio AceptaciónReproducción responsiva del reproductor de video en todos los anchos de pantalla.

3.2 Módulo Administrativo y de Gestión

RF-12: Dashboard Administrativo Central
DescripciónTablero de control con métricas en tiempo real: compras totales en CLP, recuento de productos en inventario con alerta de stock crítico (≤ 6 unidades) y número de usuarios activos.
Criterio AceptaciónCoincidencia funcional con la Figura 9 de la pauta.
RF-13: Control de Órdenes y Modal Tributario de Boleta
DescripciónTabla de pedidos con filtro por estado (Pagada, En preparación, En despacho, Entregada). Incluye modal "Mostrar Boleta" con diseño legal tributario (RUT emisor, desglose de ítems, IVA 19% e impresión).
Criterio AceptaciónCoincidencia con la Figura 10 de la pauta.
RF-14: Mantenedor CRUD de Catálogo de Productos
DescripciónOperaciones de creación, listado con buscador, edición en modal y eliminación física de productos con sincronización inmediata en LocalStorage. Pestañas de filtrado para productos críticos y en oferta.
Criterio AceptaciónLos cambios impactan el catálogo público en tiempo real sin reiniciar la aplicación.
RF-15: Mantenedor CRUD de Categorías
DescripciónAdministración de categorías del catálogo con actualización en cascada de los productos vinculados.
Criterio AceptaciónPersistencia estructurada en la entidad de categorías.
RF-16: Mantenedor de Usuarios e Historial Comercial
DescripciónGestión de cuentas con asignación de roles (Cliente, Vendedor, Administrador) y visor detallado de pedidos históricos por usuario.
Criterio AceptaciónAcceso exclusivo para rol Administrador.
RF-17: Reportes Financieros y de Gestión
DescripciónInforme consolidado de facturación bruta, total de descuentos concedidos, recaudación de IVA fiscal y ranking de productos de mayor demanda.
Criterio AceptaciónCálculos matemáticos derivados automáticamente del registro de órdenes pagadas.
RF-18: Perfil Administrativo y Seguridad
DescripciónMódulo para actualización de datos personales y cambio autenticado de contraseña administrativa.
Criterio AceptaciónValidación de coincidencia de clave previa antes de actualizar la persistencia.

4. Requerimientos No Funcionales (RNF)

Código Requerimiento Descripción Técnica Métrica
RNF-01 Responsividad Multidispositivo La interfaz debe adaptarse fluidamente a pantallas de móviles (≥360px), tablets (768px) y escritorios (1200px+). 100% de vistas adaptadas
RNF-02 Responsabilidad Única (SRP) Cada componente React debe encapsular una única responsabilidad lógica y visual. Bajo acoplamiento verificado
RNF-03 Rendimiento y Latencia Transición de rutas y filtrado reactivo del catálogo en tiempo imperceptible. < 100 milisegundos
RNF-04 Aseguramiento de Calidad Batería de pruebas automatizadas con Jasmine y Karma sobre Chrome Headless. 10 de 10 tests aprobados
RNF-05 Seguridad de Accesos Rutas administrativas protegidas mediante guardias de sesión en React Router. Bloqueo no autorizado 100%
RNF-06 Accesibilidad Web Uso de etiquetas semánticas y contraste conforme a lineamientos WCAG 2.1 nivel AA. Contraste ≥ 4.5:1

5. Modelo de Datos Lógico (JavaScript Schema)

La persistencia reactiva en src/services/db.js opera bajo los siguientes esquemas estructurados:

// Definición de Esquemas en TypeScript / JavaScript
interface Producto {
  id: string;               // Identificador alfanumérico SKU (ej: 'TC001')
  nombre: string;           // Nombre comercial del producto
  categoria: string;        // Categoría oficial asignada
  precio: number;           // Precio unitario en CLP (IVA incluido)
  precioAnterior?: number;  // Precio original tachado en ofertas
  stock: number;            // Stock físico disponible en inventario
  descripcion: string;      // Reseña organoléptica y porciones
  imagen: string;           // Ruta relativa al archivo de imagen
  destacado: boolean;       // Banner promocional en página de inicio
  enOferta: boolean;        // Inclusión en catálogo de ofertas
}

interface Orden {
  id: string;               // Identificador interno correlativo (ej: 'ORD-20240705')
  numeroOrden: string;      // Número visible en boleta electrónica (ej: '20240705')
  fecha: string;            // Timestamp en formato estándar ISO
  cliente: {
    nombre: string;
    apellidos: string;
    correo: string;
    direccion: string;
    region: string;
    comuna: string;
    indicaciones?: string;
  };
  items: Array<{
    id: string;
    nombre: string;
    precio: number;
    cantidad: number;
    subtotal: number;
    imagen: string;
  }>;
  subtotal: number;
  descuento: number;
  cupon: string | null;
  iva: number;              // Débito fiscal 19% incluido legal
  envio: number;            // Costo de despacho ($3.990 o $0 si subtotal > $30.000)
  total: number;            // Total final facturado en CLP
  estado: 'Pagada' | 'En preparación' | 'En despacho' | 'Entregada';
}
